# Local COD automation

From `server/automation/n8n`, copy `.env.example` to `.env`. Required n8n variable names are `N8N_WEBHOOK_SECRET`, `N8N_SERVICE_TOKEN`, and `NEXAMART_API_BASE`. Generate independent credentials in a local secret manager and configure them without displaying or committing their values. The API base must be reachable from the container. Never commit `.env`.

Before enabling COD, apply the Server migrations to a local PostgreSQL database. From `server/` in PowerShell, with a local `DATABASE_URL` configured and `NODE_ENV` unset or set to `development`, run:

```powershell
npm.cmd run db:migrate
Set-Item Env:N8N_ACTOR_PROVISION 'local-confirmed'
npm.cmd run n8n:actor:provision:local
Remove-Item Env:N8N_ACTOR_PROVISION
```

The command prints the dedicated `N8N_ACTOR_ID` UUID and a `Set-Item Env:N8N_ACTOR_ID '...'` next-step command. Run that printed command or copy the UUID into `server/.env`. Repeating provisioning returns the same UUID. It creates only a `service_actors` row, never a human account, password, or token. It refuses production and remote database targets. `order_events.service_actor_id` and `service_audit_records.service_actor_id` then record n8n attribution; human account actor IDs remain separate.

Required Server variable names are `N8N_COD_ENABLED`, `N8N_ACTOR_ID`, `N8N_SERVICE_TOKEN`, `N8N_WEBHOOK_SECRET`, and `N8N_WEBHOOK_URL`. The webhook URL must point to the local NexaMart COD webhook registered by this workflow. The tracked Compose file already sets `NODE_FUNCTION_ALLOW_BUILTIN=crypto` and `N8N_BLOCK_ENV_ACCESS_IN_NODE=false`, which the signature-verification Code node requires. Start a dedicated local instance with `docker compose up -d`; n8n is bound to localhost port 5678. Import the two NexaMart JSON files through n8n's workflow import UI, activate them, and configure n8n's local owner account.

Create a COD order through the authenticated checkout API. An authorized local operator can invoke `POST /api/cod/local/dispatch` with the dedicated service bearer credential to send due outbox records. For automatic dispatch on the single local API process, set `NEXAMART_LOCAL_OUTBOX_DISPATCH_ENABLED=1` in the ignored `server/.env` and restart Server; while it runs, a non-overlapping tick checks due events every five seconds. This local-only switch is inert in production and when COD automation is disabled. In production/serverless, use a separately provisioned authenticated external scheduler and shared-safe outbox claims; this local timer is not a durable production scheduler. The dispatch response reports `attempted`, `delivered`, `failed`, `exhausted` (newly failed at the limit), and `skipped` (concurrent claims), without a payload or credential. Dispatch atomically claims a due row, retries failures up to five attempts, and never resends a row marked delivered. A crash after claim can cause a later retry; n8n must deduplicate the stable `eventId`. Local automatic delivery requires both API and n8n to remain running. The reminder workflow polls `GET /api/cod/local/pending-confirmation` hourly. n8n callbacks use `POST /api/cod/local/callback` with the same service credential, a stable `eventId`, `orderItemId`, and one allowed action. They still pass Server transition rules; only the authorized shipped-to-delivered collection transition can collect COD money.

For a **dedicated** NexaMart n8n instance, keep successful and failed execution records with `EXECUTIONS_DATA_SAVE_ON_SUCCESS=all` and `EXECUTIONS_DATA_SAVE_ON_ERROR=all`. Bound local retention with `EXECUTIONS_DATA_PRUNE=true`, `EXECUTIONS_DATA_MAX_AGE=168` (hours), and `EXECUTIONS_DATA_PRUNE_MAX_COUNT=10000`. These are instance-wide settings: on a shared n8n instance, inspect its existing retention policy and do not change it for NexaMart. After dispatch, open the NexaMart COD workflow's **Executions** tab and verify a successful run for the expected event ID; inspect only that workflow's execution details and the local operator log. [n8n documents these settings](https://docs.n8n.io/deploy/host-n8n/configure-n8n/basic-configuration/use-environment-variables/executions).

For a dedicated instance managed by this Compose file, `docker compose restart n8n` restarts the existing container. After changing Compose environment settings, use `docker compose up -d --no-deps --force-recreate n8n` to apply them while retaining the named volume. Do not run these commands against another project's n8n instance. Existing unrelated workflows must not be touched, imported over, renamed, disabled, deleted, or changed.

The webhook checks an HMAC SHA-256 signature over `<unixSeconds>.<rawJson>` in `x-nexamart-signature`, with seconds in `x-nexamart-timestamp`; its replay window is five minutes. n8n uses event IDs to suppress duplicates. Keep clocks synchronized. The static-data deduplication store is local and should not be treated as a durable queue.

## Telegram order operations

Apply Server migration `0024_customer_telegram_links.sql` before enabling the link UI. Configure the dedicated NexaMart bot in local n8n using the variable names `NEXAMART_TELEGRAM_BOT_TOKEN` and `NEXAMART_ADMIN_TELEGRAM_CHAT_ID`. Configure `TELEGRAM_BOT_USERNAME` on Server only after the bot and the link-poll workflow are active. These are names only; keep all values in local secret configuration. The Admin destination is an operator-configured n8n setting, never an Admin-entered customer chat ID. Do not use a bot or chat belonging to another project.

Update **only** the NexaMart COD order operations workflow from `workflows/cod-order-operations.json`. It retains the signed `nexamart-cod` webhook and existing COD operational branches. Import the separate NexaMart `workflows/telegram-customer-link-poll.json` workflow and activate it only when this dedicated bot has no Telegram webhook. [Telegram's Bot API](https://core.telegram.org/bots/api#getupdates) does not allow `getUpdates` while a webhook is set; do not remove an existing webhook or alter unrelated workflows to make polling work. The poll workflow uses a one-minute schedule and can also be run manually. Local n8n requires no public Telegram callback endpoint for this polling path.

After updating either workflow or its local environment, restart the existing local n8n service through the same launcher that started it; for the dedicated Compose instance use the restart instructions above. Confirm both NexaMart workflows are active before dispatching notification events. Keep the other project's workflow records and activation states unchanged.

An authenticated customer may save an international-format Telegram contact number in Account. That number is private customer metadata only; it is never sent in the outbox, used for bot identity, or used as a delivery target. The customer then requests a 10-minute, single-use bot start link and presses **Start** in a private chat with the dedicated NexaMart bot. Polling validates that the Telegram user ID equals the private chat ID, then calls the service-authenticated Server link endpoint. Server stores a hash of the one-time code and binds the verified private chat ID to the account that requested it. Replaying or using an expired code cannot create or alter a link. Account distinguishes `not_linked`, `link_pending`, `linked`, and actionable errors; it never equates a saved number or pending link with enabled delivery.

Requesting a new link immediately disconnects any previously linked chat until the new Start completes. **Unlink Telegram** revokes the chat and any outstanding challenge; removing the optional contact number is separate. A chat already linked to another account is rejected and shown as a link error. The recipient for each `order.status_updated` event is resolved at dispatch time; an event already acknowledged as `skipped_unlinked` is not resent after a later link. Update only the NexaMart customer-link polling workflow from its tracked JSON, then republish it. Reload that workflow only when doing so will not interrupt another project's active poller; leave every other project's workflow and credentials unchanged.

Checkout writes one `order.created` notification event per successful order inside the same database transaction as the order, alongside existing per-line COD operational events. The signed n8n workflow sends the Admin a minimal COD order message. Admin line updates write `order.status_updated` only after an allowed Server transition. n8n resolves the customer chat through the service-authenticated order-owner lookup. An unlinked owner yields `skipped_unlinked` without a Telegram send. The persistent outbox records `telegram_sent` or `skipped_unlinked` only when n8n acknowledges that outcome with the same event ID; an invalid acknowledgement is retried up to the existing five-attempt limit. Local automatic dispatch requires the explicit Server flag described above; otherwise operators invoke dispatch manually. n8n cannot update payment or fulfillment state through these notification events.

Check activation and executions on these two NexaMart workflows only. For a test order, inspect the order's `order.created` and `order.status_updated` outbox rows and their `delivery_outcome`, then confirm the intended chat received one matching reference and status. Re-dispatch a delivered row to confirm it is not resent. A crash between a successful Telegram send and n8n saving deduplication state can still cause a duplicate on retry because Telegram `sendMessage` has no idempotency key. Treat `telegram_sent` as an acknowledged send, not proof of customer reading or delivery. Never copy execution data, chat IDs, bot tokens, service tokens, or link codes into logs, issues, or source control.

Stop a dedicated instance managed by this Compose file with `docker compose down`; keep its named volume. Never delete a shared n8n volume because it may contain unrelated workflows and execution history. Local n8n cannot receive public provider callbacks without secure public HTTPS exposure. This setup contains no payment gateway or courier integration.
